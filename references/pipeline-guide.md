# 八阶段流水线执行指南

本文档是 video-shotcraft skill `pipeline.md` 的实操指南，补充宣传片场景的具体执行方法。
执行时以 video-shotcraft 的 `pipeline.md` 为权威，本文件提供实操要点和防坑提醒。

---

## 阶段 0：产品理解

**输入**：用户描述的产品/企业信息，或产品官网 URL。

**执行**：
1. 识别产品核心卖点（效率？体验？生态？智能？）
2. 识别目标受众（开发者？企业决策者？普通用户？）
3. 列出必须展示的功能（按重要性排序，3-4个为佳）
4. 识别数据风险：截图是否包含真实用户数据？是否需要脱敏？
5. 确认画幅（默认1920×1080横屏）、时长（默认33-40秒）、语言

**产出**：产品简报 + 需求决策表 + 数据约束

**防坑**：不要在这一步写任何视频代码。数据风险必须在这一步识别，不能拖到阶段5。

---

## 阶段 1：视觉方向

**输入**：产品简报

**执行**：
1. 选择视觉方向（不确定时默认暗场霓虹）
2. 定义色板：底色、品牌色、辅助色、文字色
3. 定义字体（系统默认字体优先）
4. 确定截图素材的融入方式（直接贴/加滤镜/加遮罩）
5. 定义文字层级（至少3级：mega标题/字幕/辅助标签）

**色板选择参考**：
- 科技/SaaS → 暗场霓虹（深底#06080F + 品牌色高光）
- 消费品 → 明亮干净（白底 + 品牌色点缀）
- 金融/企业级 → 深色专业（深蓝/深灰底 + 低饱和色）
- 教育/课程 → 温暖明亮（暖白底 + 活力色）

**产出**：styleframe（HTML静帧）+ 色板 + 字体规范

**防坑**：styleframe 是契约，不是装饰。后面所有镜头都要对齐这个方向。如果 styleframe 看着像PPT动画——方向错了，重来。

---

## 阶段 2：功能到镜头映射

**输入**：产品简报 + 视觉方向

**执行**：
1. 把"必须展示功能"映射到镜头卡片类型（参考 `shot-card-catalog.md`）
2. 设计能量骨架：
   - ① 品牌开场 ~9%
   - ② 单主角立传 ~11%
   - ③ 功能爬升 ~58%（3-4个功能镜头 + 呼吸字卡交替）
   - ④ 收场 ~13%
3. 确定总镜头数（7-11个为佳）

**产出**：镜头列表（编号 + 卡片类型 + 展示什么功能）

**防坑**：每个功能用最适合它的卡片类型，不是所有功能都用同一种卡。功能镜头之间用呼吸字卡隔开形成节奏。

---

## 阶段 3：分镜与制作放行

**输入**：镜头列表 + 视觉方向

**执行**：
1. 为每个镜头分配精确帧号（from + dur）
2. 编写关键动效描述
3. 如果有 BGM，计算节拍网格并对齐切换点
4. 制作放行检查（确认后才进入实现）

**时间线设计**：
- 30fps
- 功能镜头 100-150帧（3.3-5秒）
- 呼吸字卡 50帧（1.7秒）
- 总时长 1000-1200帧（33-40秒）

**分镜表格式**：
```
| # | from | dur | 镜头 | 关键动效 |
|---|------|-----|------|---------|
| S1 | 0 | 100 | brand-ink-open | 十字准线→字标压印→退场 |
```

**产出**：完整分镜表 + theme.ts（时间线/色板/缓动/文字尺寸）

---

## 阶段 4：素材采集

**输入**：分镜表

**执行**：
1. 截取产品官网/界面截图 → `public/textures/`
2. 从 SFX 库选择匹配的音效（参考 `sfx-mapping.md`）
3. 选择 BGM（或由用户指定）
4. **核对 SFX 文件名**：`find public/audio/sfx -name "*.mp3" | sort`

**截图采集方法**：
- 用浏览器截取产品页面的完整长图
- 按分镜表需要的区域裁剪
- 隐私检查：如果包含真实用户数据，标记为"必须暗化"

**产出**：textures/*.png + 确认的 SFX 文件列表 + BGM 文件

**防坑**：SFX 文件名必须用真实路径，禁止占位名。这是翻车率最高的坑。

---

## 阶段 5：逐镜头实现

**输入**：分镜表 + 素材

**执行**（每个镜头都走这个循环）：
1. 写镜头组件 `.tsx`
2. 注册到 `Main.tsx` 的 `<Sequence>`
3. 渲染代表帧：`npx remotion still src/index.tsx <id> out/qa/sN-fXX.png --frame=XX`
4. 肉眼检查（看检查清单）
5. 有问题 → 修改 → 回到步骤3
6. 通过 → 下一个镜头

**单帧 QA 检查清单**：
- [ ] 背景是否符合视觉方向
- [ ] 主体内容是否聚焦
- [ ] 所有可见文字 ≥ 56px（字幕）或 ≥ 32px（标签）
- [ ] 是否有真实用户数据暴露
- [ ] 动效时间线是否合理
- [ ] 是否有 CSS 属性写错

**防坑**：参见 `anti-pit-rules.md` 全部规则。特别是：导入名匹配、prop名精确、Easing参数、暗化方案、隐私保护。

**产出**：所有镜头组件 + Main.tsx + QA 截图

---

## 阶段 6：声音设计

**输入**：完成的镜头 + SFX 文件 + BGM

**执行**：
1. 编写 SFX 钉帧表（`{ from, src, volume, dur? }[]`）
2. from 用相对表达式 `SHOTS.x.from + offset`
3. 长样本（>5s）必须给 dur
4. BGM 音量 0.3-0.35
5. 创建 `props-nobgm.json`
6. 双版本渲染验证

**产出**：完整 SFX 钉帧表 + props-nobgm.json

---

## 阶段 7：独立终检与交付

**输入**：完成的视频代码

**执行**：
1. 派干净上下文 subagent，给它 `final-review.md` + `aesthetic-rules.md`
2. subagent 逐条检查，产出结构化报告（P0/P1）
3. 主 Agent 逐条修复 P0
4. 渲染双版本 MP4
5. ffprobe 验证规格一致
6. volumedetect 验证音频差异（5-8dB）
7. 抽帧做最终视觉确认
8. 交付

**产出**：promo.mp4 + promo-nobgm.mp4 + 终检报告
